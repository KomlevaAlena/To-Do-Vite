# 🎯 Общая цель проекта

**Todo List (Vanilla JS, Vite, Sass)**
Цель проекта — освоить:

* модульную структуру JavaScript
* разделение логики / представления / данных
* работу с DOM без фреймворков
* базовый стейт приложения
* постепенное усложнение без переписывания всего проекта

---

# 🧱 Архитектура (сразу, но просто)

Сразу заложим правильную мысль, **даже если реализация сначала примитивная**.

```txt
src/
 ├─ js/
 │   ├─ app.js          // точка входа
 │   ├─ state.js        // состояние приложения
 │   ├─ todo/
 │   │   ├─ todoModel.js
 │   │   ├─ todoView.js
 │   │   └─ todoController.js
 │   └─ utils/
 │       └─ createElement.js
 ├─ styles/
 │   └─ main.scss
 └─ index.html
```

👉 **HTML минимальный**, всё содержимое — из JS.

# 🧩 ЭТАП 1. «Для самых маленьких» (база)

### 🎯 Цель

Понять:

* как JS создаёт HTML
* как работает обработка событий
* как отделять код по файлам

### 📌 Функциональные требования

**Todo умеет:**

* показывать заголовок «Todo List»
* показывать список задач
* добавлять задачу через input + кнопку
* удалять задачу

**Ограничения:**

* задачи хранятся **в массиве в памяти**
* без localStorage
* без фильтров
* без галочек

### 📌 Поведение

* пустая задача не добавляется
* после добавления input очищается

### 📌 Технические требования

* HTML списка создаётся **из JS**
* каждый модуль делает **только одну вещь**
* никакого глобального кода

### 🧠 Чему ты тут учишься

* `document.createElement`
* `append`
* `addEventListener`
* передача данных между модулями
* базовый стейт

# 🧩 ЭТАП 2. «Уже разработчик» (функциональность)

### 🎯 Цель

Освоить:

* состояние приложения
* перерисовку UI
* работу с данными

### 📌 Новые функции

* отметить задачу как выполненную
* хранить статус `completed`
* визуально различать выполненные задачи
* счётчик задач:

  * всего
  * выполнено
  * осталось

### 📌 Поведение

* кликом по чекбоксу задача переключает состояние
* UI обновляется полностью из состояния

### 📌 Технические требования

* `state.js` — единственный источник правды
* View не хранит данные
* Controller связывает события и состояние

### 🧠 Чему ты тут учишься

* immutable-мышление (не мутировать массивы бездумно)
* обновление UI через состояние
* separation of concerns (очень важная штука)
